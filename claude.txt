## 2. Nav linking to other pages (not just `#anchors`)

Right now your links use `#home`, `#news` etc — those jump to sections *within the same page*. To go to different HTML files instead:

```html
<div class="topnav">
  <a class="active" href="index.html">Home</a>
  <a href="news.html">News</a>
  <a href="contact.html">Contact</a>
  <a href="about.html">About</a>
</div>
```
You'd then create `news.html`, `contact.html`, `about.html` as separate files in the same folder as `index.html`. Each is its own full HTML document (with its own `<head>`, `<body>`, etc.), and can link to the same `styles.css` so they all share your nav styling.

## 4. Pulling data from the internet (JavaScript `fetch`)

This calls a public API and drops the result into your page. Example using a free test API:

```html
<div id="quote-box">Loading...</div>

<script>
  fetch('https://api.quotable.io/random')
    .then(response => response.json())
    .then(data => {
      document.getElementById('quote-box').textContent = data.content;
    })
    .catch(error => {
      document.getElementById('quote-box').textContent = "Couldn't load quote.";
    });
</script>
```
What's happening: `fetch()` makes a network request, `.then(response => response.json())` parses the reply as JSON, and the next `.then` takes that data and writes it into your `<div>` using its `id`. This is the core pattern almost all "pull from the internet" features use — weather widgets, live scores, etc. — just pointed at different APIs.
